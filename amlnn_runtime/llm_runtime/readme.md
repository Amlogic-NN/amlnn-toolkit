# llm_runtime: Amlogic LLM C/C++ SDK

`llm_runtime` provides the C/C++ inference SDK for deploying **large language models** on Amlogic NPU platforms. Link against `libllmsdk.so` and include `llmsdk.h` to integrate LLM inference into native applications. Supports Android and Linux (Yocto / Debian) platforms.

## Key Features

- **Multi-platform support**: Android, Linux Yocto, and Linux Debian — 32-bit and 64-bit libraries included.
- **Streaming output**: Token-by-token generation via callback.
- **Multi-turn conversation**: Optional history retention across calls.
- **Built-in chat templates**: Supports Qwen, Llama, DeepSeek, Gemma, and more.

## Environment Setup

### Prerequisites

- **NPU Driver**: 2.0.2 or higher

### 1. Verify NPU Driver

Check the NPU driver version on the target device. Version **2.0.2 or higher** is required.

**Android:**

```bash
adb root
adb shell
dmesg | grep adla
# 64-bit
strings /vendor/lib64/libadla.so | grep LIBADLA
# 32-bit
# strings /vendor/lib/libadla.so | grep LIBADLA
```

**Linux (Yocto / Debian):**

```bash
adb shell
dmesg | grep adla
strings /usr/lib/libadla.so | grep LIBADLA
```

Expected output:

```
adla kmd version: 2.0.2.x.x
LIBADLA, v2.0.2.x.x.x, 20xx.xx
```

> **IMPORTANT**: If the driver version is too old, re-flash the device with the latest image. Contact your FAE or after-sales team for the image file.

### 2. Install CMake

Download and configure CMake. Recommended version 3.16.3 or higher. Example using cmake-3.24.0-linux-x86_64:

```bash
# Download cmake-3.24.0-linux-x86_64.tar.gz from the CMake official website

# Extract to a local directory
tar -xzf cmake-3.24.0-linux-x86_64.tar.gz -C /opt/

# Add to PATH
echo 'export PATH=/opt/cmake-3.24.0-linux-x86_64/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

cmake --version
```

### 3. Install Cross-Compilation Toolchain

Choose the toolchain for your target platform:

**Android**

Download [android-ndk-r25c](https://github.com/android/ndk/wiki/Unsupported-Downloads), extract to a local directory (e.g. `/opt/android-ndk-r25c`), then update `ANDROID_NDK_PATH` on line 4 of `build-android64.sh` or `build-android32.sh`.

**Linux Yocto / Debian**

- 64-bit: Download [poky-glibc-x86_64-meta-toolchain-armv8a-mesont7-an400-5.15-a64-toolchain-4.0.20.sh](https://pub-8378326bd0fe4b1d9312a3847f6316a2.r2.dev/toolchain/yocto_toolchain/64/poky-glibc-x86_64-meta-toolchain-armv8a-mesont7-an400-5.15-a64-toolchain-4.0.20.sh)
- 32-bit: Download [poky-glibc-x86_64-amlogic-bsp-armv7at2hf-neon-mesons7-bh201-5.15-a32-toolchain-4.0.20.sh](https://pub-8378326bd0fe4b1d9312a3847f6316a2.r2.dev/toolchain/yocto_toolchain/32/poky-glibc-x86_64-amlogic-bsp-armv7at2hf-neon-mesons7-bh201-5.15-a32-toolchain-4.0.20.sh)

Run the Yocto SDK installer (`.sh`), choose an install path (e.g. `/opt/poky/4.0.20`), then update `YOCTO_TOOLCHAIN_PATH` on line 4 of `build-yocto64.sh` or `build-yocto32.sh`.

### 4. Build

```bash
cd amlnn_runtime/llm_runtime/example/base_api

# Android 64
./build-android64.sh

# Android 32
./build-android32.sh

# Linux Yocto 64 / Debian 64
./build-yocto64.sh

# Linux Yocto 32 / Debian 32
./build-yocto32.sh
```

The compiled binary is placed in `install/<platform>/base_api_llm`.

## Quick Start

After building, push the binary, SDK library, and model to the board and run.

```bash
# Example: Android 64
adb root
adb push install/android64/base_api_llm /data/local/tmp/

adb push /path/to/model.adla /data/local/tmp/

adb shell

cd /data/local/tmp
./base_api_llm model.adla --model_type qwen
```

On success, you will enter an interactive chat interface where you can type prompts directly.

## Demo Overview

`base_api_llm.cpp` covers the full LLM inference workflow:

1. **Init**: Calls `aml_llm_init` to load the `.adla` model and register the token callback.
2. **Set chat template** (optional): Calls `aml_llm_set_chat_template` with a built-in template based on `--model_type`.
3. **Interactive loop**: Waits for user input, calls `aml_llm_run` to run inference, and streams tokens via the callback.
4. **Interactive commands**: `new_talk` resets conversation history, `break` interrupts the current generation, `exit` quits.
5. **Cleanup**: Calls `aml_llm_uninit` to release resources.

### Parameters

```
base_api_llm <model_path> [--model_type <type>]
```

| Parameter | Description |
| :--- | :--- |
| `model_path` | Path to the compiled `.adla` LLM model file, generated by `amlnn_toolkit` |
| `--model_type` | Built-in chat template to apply. See table below. Omit to use the model's default template. |

### Supported Model Types

| `--model_type` | Model |
| :--- | :--- |
| `qwen` | Qwen, InternVL |
| `deepseek` | DeepSeek |
| `gemma` | Gemma |
| `gemma3` | Gemma3 |
| `llama` | Llama |
| `tiny_llama` | TinyLlama |
| `tiny_llama_v0_4` | TinyLlama v0.4 |
| `phi_1_5` | Phi-1.5 |
| `phi_2` | Phi-2 |
| `minicpm4` | MiniCPM4 |
